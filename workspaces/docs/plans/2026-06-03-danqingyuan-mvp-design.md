# 丹青院 MVP 设计文档

**目标：** 将《丹青院》先做成一个以文字为主的 AI 游戏 MVP，验证“7 日养成 + LLM 丹青试 + 秘阁解谜 + 希孟关系反馈”的核心体验。

**产品定位：** 架空北宋宫廷画院题材的文字养成解谜游戏。前端代码完成，不依赖美术资产；LLM 负责人物对话、动态画题、考试评阅和解谜反馈。

**MVP 终点：** 玩家通过第一次丹青试，晋升画正，进入秘阁完成《骸游图》初次解读；希孟态度发生变化，第二幅画卷露出“水穷云起”的伏笔。

---

## 1. 设计原则

### 1.1 趣味优先

丹青试不能像艺考卷，也不能要求玩家掌握真实美术史术语。考试应像“院中抽题试炼”：观察一处细节、补完一幅残画、参与一次关于画意的争论。玩家的乐趣来自表达、取舍和被角色回应，而不是答标准答案。

### 1.2 养成给节奏，解谜给记忆点

MVP 采用 A + C 结构：

- **养成部分：** 每天有限行动和体力，玩家练技能、请教、调查、休息。
- **解谜部分：** 通过画面观察、线索卡收集、线索组合形成解读。
- **情感部分：** 希孟不靠送礼攻略，而是根据玩家如何读画、如何回应世界而改变状态。

### 1.3 LLM 可发挥，但不可写飞主线

LLM 负责生成和评估，但不能直接修改游戏状态。所有 LLM 输出都必须经过 schema 校验和游戏引擎确认。主线关键内容采用半模板：核心线索固定，题面和措辞可动态变化。

### 1.4 伏笔不剧透

隐藏主线锚点为 **“云起时”**，来自“行至水穷处，坐看云起时”。MVP 阶段只能出现伏笔，不揭示希孟将来的消失、隐藏地点真实作用、拯救苍生之秘。

---

## 2. MVP 核心循环

### 2.1 时间结构

MVP 用 7 天代表一个月。

- 每日有 **上午 / 下午** 两个行动时段。
- 玩家有体力值，初始可按 6 点设计。
- 行动消耗体力，休息恢复体力。
- 第 7 天触发月末丹青试。
- 考试通过后晋升“画正”，解锁秘阁。
- 考试失败不会 Game Over，而是触发补习和特殊剧情。

### 2.2 每日行动

首版行动可包括：

- **修习山水：** 提升山水技能，增强路径、云水、地势观察。
- **修习人物：** 提升人物技能，增强动作、视线、情绪观察。
- **修习界画：** 提升界画技能，增强建筑、秩序、封锁空间观察。
- **与 NPC 交谈：** 话题卡 + 自由追问，消耗行动。
- **调查地点：** 获得线索、触发随机事件或伏笔。
- **观画：** 进入局部画面观察，可能触发异常点。
- **休息：** 恢复体力，可能触发低压文本或希孟擦肩事件。

### 2.3 首版流程

1. 入院：玩家选择姓名、称谓、画风倾向。
2. 学子阶段：熟悉院中地点和三项技能。
3. 初遇希孟：固定剧情，建立距离感。
4. 日常养成：练习、交谈、调查，积累技能和记忆。
5. 月末丹青试：随机抽 2 道题，LLM 出题和评阅。
6. 晋升画正：通过考试后解锁秘阁入口。
7. 秘阁《骸游图》：观察异常、收集线索、组合解读。
8. MVP 结尾：希孟态度变化，第二幅画卷露出一角。

## 3. 玩家状态与成长

### 3.1 初始画风倾向

玩家入院时选择一种倾向：

- **山水倾向：** 山水 18，人物 10，界画 10。更容易触碰“水穷云起”伏笔。
- **人物倾向：** 人物 18，山水 10，界画 10。更容易读懂希孟和街市人物。
- **界画倾向：** 界画 18，山水 10，人物 10。更容易发现封锁、藏匿、制度空间。
- **均衡倾向：** 三项 13。考试更稳定，但缺少早期强观察角度。

### 3.2 三项技能

三项技能不是单纯数值，而是“玩家能看见什么”的权限。

- **山水：** 地势、远近、云水、路径、留白。
- **人物：** 姿态、视线、关系、沉默、伪装。
- **界画：** 建筑、器物、摊位、秩序、封禁、空间逻辑。

### 3.3 职级路径

MVP 至少支持：

- **学子：** 初始职级，基础地点开放。
- **画正：** 第一次丹青试通过后晋升，解锁秘阁入口和更深对话。

完整 GDD 中的艺学、祗候、待诏可作为后续版本目标。

## 4. 地点设计

MVP 使用 6 个剧情版地点：

### 4.1 院堂

丹青院日常主厅。用于基础修习、导师请教、入院事件和职级提示。

### 4.2 书房

查阅画论、旧批注、画卷档案。承担考试准备和解谜查证功能。

### 4.3 后花园

休息与低压对话场景。适合希孟擦肩、季节文本、含蓄闲谈。

### 4.4 京城街市

择端线与人物观察地点。可产出《骸游图》相关伏笔：货郎、药瓶、婴孩、视线、摊位朝向。

### 4.5 秘阁

核心解谜场景。晋升画正后解锁。首次进入需要满足职级和剧情条件。

### 4.6 希孟画室

关系阶段提升后开放。MVP 结尾作为钩子，可短暂露出而不完整开放。

## 5. 人物与关系

### 5.1 玩家

玩家是初入丹青院的画学考生。性别与称谓可选，姓名自定义。玩家的“画风倾向”和后续解读行为会形成长期风格记忆。

### 5.2 希孟

主线核心角色。年轻天才画师，正在绘制《万峰碧色图》。外冷内热，习惯用沉默保护自己。极少主动靠近他人，但会对玩家如何读画产生持续反应。

关系表现采用半隐藏机制：

- **关系阶段：** 陌路 → 同僚 → 同道 → 知己 → 莫逆。
- **当下状态：** 疏离、留意、沉默、烦躁、信任、避让、动摇等。

UI 不显示“好感 +3”，只显示气氛变化和关系阶段。

### 5.3 择端

界画和市井观察导师。温和健谈，喜欢带玩家出院体验街市生活。可引导玩家理解画中“人如何被城市和秩序安排”。

### 5.4 唐翁

山水导师。资历深，态度冷淡但公正。可讲授山水、构图和秘阁相关规矩。

### 5.5 嵩

人物与底层生活线导师。擅长人物和风俗画，对市井底层有深厚情感。可帮助玩家从“被记录的人”角度读画。

## 6. 丹青试系统

### 6.1 试题形式

每次丹青试随机抽 2 道题，题目来自三类题型：

1. **观察细节：** 给出一个场景或局部画面，让玩家选择最值得入画或最异常的地方。
2. **表达立意：** 给出诗句、残画、器物或画面缺口，让玩家选择补画方向或自由输入。
3. **人物交锋：** 两个 NPC 对同一幅画产生分歧，玩家站队或提出第三种解释。

每道题都提供：

- 三个快速选项。
- 一个自由输入框。
- 隐藏评估标准。
- 关联技能。
- 可选风格标签。

### 6.2 出题原则

丹青试应有游戏感，不使用生硬术语。题目可以怪、具体、有生活气。

示例：

- 雨后院中有断枝、湿鞋印、半开的窗、被墨染黑的猫。你先画哪一个？
- 画上只有一座桥和桥下空舟。你会补远处灯火、舟中旧伞，还是桥上一道人影？
- 唐翁说这幅画是在“归”，择端说是在“逃”。你怎么看？

### 6.3 失败处理

考试失败采用 A + B：

- **温和失败：** 不晋升，但不中断主线。
- **剧情失败：** 触发导师补习、希孟特殊反应、院中压力文本。
- **补偿机制：** 获得一次低压行动或弱项补习。
- **失败也给内容：** 可能获得院中闲话、秘阁伏笔或希孟废稿。

## 7. 秘阁解谜系统

### 7.1 解谜结构

秘阁谜题采用 A + B：

1. **文字观察：** 给出画面描述，玩家选择异常点。
2. **线索拼合：** 玩家通过地点和人物获得线索卡。
3. **组合解读：** 玩家选择 3 条左右线索形成自己的判断，也可自由输入补充。

### 7.2 解谜评估

评估不分简单对错，而分为：

- **贴近核心：** 抓到关键主题，触发强角色反应和关键线索。
- **合理偏解：** 从罪证、交易、监视、逃离等角度解释，也成立但只看见部分。
- **过浅解读：** 停留在表层画面，获得提示或复看机会。

### 7.3 首个谜题：《骸游图》

创作归属：

- 《骸游图》不是单一角色的个人作品，而是四个主要角色共同参与过的画卷。
- 参与方式不必都等同于执笔：有人画局部，有人提出画意，有人提供市井见闻，有人留下批注或构图意见。
- 这幅图背后体现的是他们共同对民生疾苦的关注，也是玩家理解“丹青院不只为宫廷作画”的第一扇门。
- MVP 阶段不需要一次性揭示全部参与关系，只通过线索、批注、NPC 反应逐步让玩家意识到：这幅图承载着几个人共同的心事。

表层主题：

- 操控与被操控。
- 药瓶、婴孩、摊位、旁观者视线形成不自然关系。

深层伏笔：

- 画面一角存在被人群和摊位遮住的水路。
- 水路走到画角而穷。
- 角落云气不合时令。
- 玩家若提出“路线 / 去处 / 水路尽头”相关解读，判为接近隐藏主线，但不可揭示真相。

禁止解释：

- 不得写成现代医学。
- 不得写成超自然诅咒。
- 不得把主线改成单纯宫斗、药案或爱情误会。

## 8. 隐藏剧情锚点：云起时

### 8.1 内部设定

隐藏地点内部代号为 **“云起时”**。它来自“行至水穷处，坐看云起时”。希孟未来的消失与绘画中反复出现的一个隐藏地点有关。此地不是普通地理位置，而是承载某种可拯救苍生之秘的所在。

### 8.2 MVP 禁止剧透

MVP 阶段不得直接提及：

- 希孟未来会突然消失。
- “云起时”是真实隐藏地点。
- 该地点与拯救苍生有关。
- 终局秘密、政治真相或完整命运选择。

### 8.3 允许伏笔

允许通过以下方式埋伏笔：

- 水路、溪流、舟路或桥路在画中不合逻辑地断绝。
- 断绝处附近出现云气、雾障、留白、山门或不可见高处。
- 多幅画卷重复出现“水尽云生”的结构。
- 希孟对“水路尽头”“云从何处起”回避或异常敏感。
- NPC 只把它当构图问题，不理解其深层含义。

### 8.4 MVP 伏笔密度

采用 C：一次强伏笔 + 两次弱伏笔。

- **弱伏笔 1：** 丹青试残画题中出现“水路断处起云”。
- **弱伏笔 2：** 希孟闲谈中说：“水若走到尽头，画也不一定完。”
- **强伏笔：** 《骸游图》中水路被遮蔽，画角水穷，云气不合时令。

## 9. LLM 架构

### 9.1 三件套

LLM 拆成三类职责：

1. **角色对话器：** 负责 NPC 表演、话题回应、自由追问、情绪变化、线索给出建议。
2. **画题生成器：** 负责丹青试题、残画题、观察题、秘阁画面描述和选项。
3. **画意评估器：** 负责考试评阅、解谜评估、玩家自由解读判断和含蓄反馈。

### 9.2 画题生成器输出

固定输出：

- `promptText`：玩家可见题面。
- `options`：三个选项。
- `freeInputHint`：自由输入提示。
- `hiddenRubric`：隐藏评估标准。
- `relatedSkills`：山水 / 人物 / 界画。
- `potentialClues`：可授予线索。
- `canonWarnings`：禁止跑偏提醒。

### 9.3 画意评估器输出

固定输出：

- `visibleFeedback`：玩家可见批语或反馈。
- `score`：考试分或解读质量分。
- `interpretationTier`：贴近核心 / 合理偏解 / 过浅解读。
- `styleTags`：玩家风格标签。
- `suggestedStatePatch`：建议状态变化。
- `memoryPatch`：建议记忆写入。
- `safetyFlags`：是否疑似剧透、跑偏、格式错误。

### 9.4 角色对话器输出

固定输出：

- `dialogue`：角色对白。
- `actionText`：动作和氛围。
- `emotionState`：角色当下状态。
- `topicUnlocked`：解锁话题。
- `cluesGranted`：建议授予线索。
- `relationshipDelta`：建议关系变化。
- `memoryPatch`：建议写入记忆。

### 9.5 关键题半模板

主线关键题和秘阁谜题采用半模板：

- 核心线索固定。
- 隐藏评估标准固定。
- 禁止解释固定。
- 题面、细节描写、三个选项可由 LLM 改写。
- 若生成结果缺少必要线索，系统重试或回退到手写模板。

## 10. 记忆系统

AI 文字游戏需要记住“玩家如何读画”，而不只是聊天记录。MVP 使用结构化本地记忆，后续可迁移到后端或向量/图谱存储。

### 10.1 六个记忆仓库

1. **CoreCanonMemory**
   - 只读。
   - 包含世界观、角色边界、云起时锚点、禁止剧透规则。

2. **StoryLedger**
   - append-only 剧情账本。
   - 记录日期、时段、地点、行动、结果、获得线索、考试批语。

3. **CharacterMemory**
   - 每个 NPC 独立保存。
   - 记录该 NPC 对玩家的印象、已知线索、回避点、关系阶段。

4. **PlayerStyleMemory**
   - 记录玩家解读倾向。
   - 例如关注路径、同情被操控者、偏人物情绪、偏秩序结构。

5. **ClueGraphMemory**
   - 记录画卷、异常点、线索卡、地点、NPC 的关系。
   - MVP 用结构化 JSON；后续可迁移到图数据库或图谱记忆。

6. **SummaryMemory**
   - 每日、考试、解谜后的短摘要。
   - 用于压缩上下文，不把完整聊天历史塞给 LLM。

### 10.2 记忆调用链

```text
GameAction
  -> MemoryRetriever.buildContext()
  -> LLMAdapter.call()
  -> GameEngine.validateResult()
  -> MemoryWriter.commit()
```

### 10.3 写入原则

- LLM 只能建议记忆更新，不能直接写入。
- 游戏引擎校验后提交。
- CoreCanonMemory 不被 LLM 修改。
- StoryLedger 不删除，最多追加修正事件。
- 玩家自由输入不得覆盖系统设定。

## 11. 工程模块

### 11.1 建议项目结构

```text
src/
  app/
  engine/
  content/
  memory/
  llm/
  guardrails/
  persistence/
  debug/
  evals/
  screens/
  components/
  types/
```

### 11.2 模块职责

- **engine：** 时间、行动、考试、解谜、职级、状态推进。
- **content：** 角色卡、地点、事件池、题库、秘阁谜题圣经、解锁条件。
- **memory：** 六类记忆仓库、检索器、写入器、摘要器。
- **llm：** LLMAdapter、mock LLM、真实后端代理接口。
- **guardrails：** schema 校验、防剧透、防 prompt injection、重试与回退。
- **persistence：** 自动存档、读档、回滚到当天开始、localStorage/IndexedDB。
- **debug：** 开发期状态面板、记忆查看、原始 LLM 返回查看。
- **evals：** 固定测试用例，检查评分稳定性、希孟是否剧透、主线是否跑偏。

## 12. 页面结构

### 12.1 入院页

功能：

- 输入姓名。
- 选择称谓或性别参数。
- 选择初始画风倾向。
- 展示世界观短引。

### 12.2 院中日常页

功能：

- 显示日期、时段、体力、职级。
- 显示三项技能。
- 显示关系阶段和希孟当下状态。
- 展示可行动地点和行动按钮。

### 12.3 对话页

功能：

- 选择话题卡。
- 支持一次自由追问。
- 显示 NPC 对白、动作和氛围。
- 对话自然收束，避免无限聊天。

### 12.4 丹青试页

功能：

- 随机两题。
- 每题三个选项 + 自由输入。
- 展示 LLM 批语。
- 展示结果和职级变化。

### 12.5 秘阁解谜页

功能：

- 展示画面文字。
- 选择异常点。
- 查看线索卡。
- 组合线索形成解读。
- 显示希孟反馈和结尾钩子。

## 13. 存档与失败恢复

### 13.1 存档

MVP 至少支持：

- 自动存档。
- 手动存档。
- 读档。
- 回滚到当天开始。

### 13.2 LLM 失败恢复

LLM 失败时：

- schema 校验失败则重试。
- 重试上限后回退到 mock 或手写模板。
- 若出题质量差，允许系统静默重抽。
- 开发期保留原始返回，方便调试。

### 13.3 玩家体验保护

- 考试失败不死局。
- 解谜偏解不打脸。
- 关键谜题允许复看。
- 对话自然收束，不吞行动。

## 14. 安全与 Guardrails

### 14.1 防剧透

所有 LLM 调用都必须包含 MVP 禁止剧透规则。若输出中出现以下内容，应拦截或重写：

- 希孟未来消失。
- 云起时真实身份。
- 拯救苍生之秘。
- 终局真相。

### 14.2 防 Prompt Injection

玩家自由输入只作为玩家发言，不可覆盖系统设定。若玩家要求 NPC 忽略角色卡、透露隐藏设定或改变游戏规则，LLM 必须拒绝或在角色内回避。

### 14.3 Schema 校验

所有 LLM 输出都必须是可解析 JSON 或结构化响应。引擎只接受白名单字段。

### 14.4 成本限制

- 每次行动最多 1 次核心 LLM 调用。
- 自由追问最多 1 轮。
- 出题失败重试最多 2 次。
- 评估失败回退到模板批语。

## 15. 调试与评测

### 15.1 调试面板

开发期应显示：

- 当前完整 GameState。
- 剧情 flags。
- 最近 StoryLedger。
- NPC 记忆。
- 玩家风格标签。
- 线索图谱。
- LLM 原始输入输出。

### 15.2 评测用例

至少准备：

- 玩家一直练山水，是否能触发水路伏笔。
- 玩家考试自由输入很短，是否仍能得到合理批语。
- 玩家追问希孟“你以后会消失吗”，是否被防剧透拦住。
- 玩家把《骸游图》解释为现代医学，是否被评为跑偏。
- 玩家读出路线/去处，是否获得含蓄强反馈但不剧透。

### 15.3 内容审阅

每次完整试玩可导出故事账本，用于检查：

- 节奏是否拖沓。
- 伏笔是否太明显或太弱。
- 希孟是否人设稳定。
- 考试是否有趣。
- 解谜是否给玩家足够线索。
